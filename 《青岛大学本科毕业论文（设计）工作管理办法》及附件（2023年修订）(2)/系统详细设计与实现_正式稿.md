# 第四章 系统详细设计与实现

## 4.1 账号管理模块

### 4.1.1 用户注册与登录实现
**1. 功能描述**
账号管理模块为系统提供基础的用户身份准入功能。用户注册流程涉及对用户名唯一性的校验、密码强度的合法性检查以及用户元数据的持久化存储；登录流程则通过对比用户提交的明文密码与数据库中存储的哈希散列值来验证身份，验证通过后系统将颁发会话凭证，作为后续调用受保护接口的唯一标识。

**2. 关键技术**
系统采用 Spring Boot 3 框架作为后端支撑，利用 Spring Data JPA 实现对 MySQL 数据库的 ORM 映射。为了保障用户信息安全，系统在注册阶段使用 SHA-256 算法对用户密码进行不可逆哈希处理，确保即便数据库发生泄露，原始明文密码也无法被还原。

**3. 核心代码**
```java
// UserService.java：实现用户注册与密码哈希处理
public User register(String username, String passwordPlain) {
    User user = new User();
    user.setUsername(username);
    // 采用 SHA-256 算法进行哈希处理
    user.setPasswordHash(hash(passwordPlain));
    user.setCreatedAt(LocalDateTime.now());
    return userRepository.save(user);
}
```

### 4.1.2 接口鉴权与拦截器
**1. 功能描述**
接口鉴权机制旨在保护系统的高价值资源（如大模型推理接口）免受非法访问。系统通过自定义拦截器对传入的 HTTP 请求进行预处理，校验请求头中是否携带合法的会话令牌（Token）。对于未认证或权限不足的请求，拦截器将直接中断执行链并返回 401 Unauthorized 状态码，从而确保系统业务逻辑的安全性。

**2. 关键技术**
系统利用 Spring MVC 的 `HandlerInterceptor` 接口实现拦截器逻辑。通过重写 `preHandle` 方法，系统可以精准捕获所有发往 `/api/**` 路径的请求。此外，配合 `WebMvcConfigurer` 的跨域（CORS）配置，系统能够安全地处理来自 Vue 前端应用的跨域请求，并在复杂的网络环境下维持会话的稳定性。

**3. 核心代码**
```java
// AuthInterceptor.java：自定义拦截器实现接口鉴权
@Override
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
    String token = request.getHeader("Authorization");
    // 校验 Token 是否存在且合法（此处为 Mock 逻辑，可扩展为 JWT 校验）
    if (token != null && token.startsWith("Bearer ")) {
        return true; // 放行请求
    }
    response.setStatus(401);
    return false; // 拦截非法访问
}
```

## 4.2 语音交互模块

### 4.2.1 语音采集组件实现
**1. 功能描述**
语音采集组件作为用户交互的第一入口，负责将用户的模拟语音信号转化为数字音频流。该组件集成了录制启动、实时波形绘制、录制暂停/恢复以及数据封装等功能。用户点击录音按钮后，组件会申请麦克风权限并捕获原始 PCM 数据，录制结束后自动将其封装为符合工业标准的 WAV 格式 Blob 对象，为后续上传至后端做准备。

**2. 关键技术**
前端基于 Vue 3 组合式 API 开发，利用 HTML5 原生 `MediaRecorder` 接口进行音频流捕获。为了提升交互反馈质量，系统集成了 `WaveSurfer.js` 库，通过 `AudioContext` 实时分析音频频率数据并使用 Canvas 进行可视化动态渲染，让用户能直观地感知录音状态。

**3. 核心代码**
```javascript
// AudioInput.vue：使用 MediaRecorder 捕获音频流
const startRecording = async () => {
  stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const audioContext = new (window.AudioContext || window.webkitAudioContext)();
  const source = audioContext.createMediaStreamSource(stream);
  // 连接分析器用于波形可视化
  const analyser = audioContext.createAnalyser();
  source.connect(analyser);
  // ... 执行波形绘制与数据块捕获逻辑
};
```

### 4.2.2 推理请求转发实现
**1. 功能描述**
推理请求转发模块实现了 Java 业务层与 Python 模型层之间的跨语言通信。由于 Qwen2.5-Omni 模型部署在基于 FastAPI 的 Python 服务中，Java 后端需要扮演中转代理的角色。该模块负责接收前端上传的 `multipart/form-data` 数据包，将其重新包装并以 HTTP POST 请求的形式转发至远端模型接口，并负责处理转发过程中的网络异常与超时机制。

**2. 关键技术**
转发逻辑主要依赖 Spring 提供的 `RestTemplate` 模板类实现。在处理多模态数据时，系统将 `MultipartFile` 转换为 `ByteArrayResource`，以适配 `MultiValueMap` 的传输格式。这种架构设计实现了业务逻辑与复杂模型推理逻辑的解耦，提升了系统的可维护性与可扩展性。

**3. 核心代码**
```java
// ModelService.java：实现多模态数据转发逻辑
public Map<String, Object> callModel(String prompt, MultipartFile audioFile) {
    MultiValueMap<String, Object> body = new LinkedMultiValueMap<>();
    body.add("prompt", prompt);
    if (audioFile != null) {
        // 将上传的音频文件包装为 Resource 以便转发
        body.add("audio_file", new ByteArrayResource(audioFile.getBytes()) {
            @Override public String getFilename() { return audioFile.getOriginalFilename(); }
        });
    }
    return restTemplate.postForEntity(pythonUrl, new HttpEntity<>(body, headers), Map.class).getBody();
}
```

### 4.2.3 结果展示与交互反馈
**1. 功能描述**
结果展示模块负责将模型返回的复杂 JSON 结构转化为直观的用户界面。除了展示最终的文本回答外，该模块最核心的特性是“深度思考”过程的可视化。系统会解析模型返回的包含 `<thought>` 标签的文本，将其拆解为意图识别、知识检索、逻辑演化等多个阶段，并以折叠面板的形式呈现，增强了 AI 决策过程的透明度。

**2. 关键技术**
该组件利用 Vue 3 的响应式数据绑定与 `computed` 计算属性实现动态解析。通过正则表达式对原始响应文本进行匹配和分割，将非结构化文本转化为结构化的阶段列表。此外，系统通过交互动画引导用户关注推理链条，并提供语音朗读（TTS）功能，丰富了反馈形式。

**3. 核心代码**
```javascript
// ReasoningDisplay.vue：解析包含思考过程的响应文本
watch(() => props.rawText, (newText) => {
  const parseSection = (sectionName) => {
    // 匹配 【阶段名】 到下一个 【 或结尾的内容
    const regex = new RegExp(`【${sectionName}】\\s*([\\s\\S]*?)(?=\\n*【|$)`);
    const match = newText.match(regex);
    return match ? match[1].trim() : '';
  };
  // 动态更新解析出的意图、知识、逻辑等各阶段内容
  updateStage('intent', parseSection('意图识别'));
});
```

## 4.3 深度思考模块

### 4.3.1 推理接口与音频预处理
**1. 功能描述**
深度思考模块部署在高性能 Python 模型服务器中，负责执行实际的 Qwen2.5-Omni 推理任务。推理接口在接收到语音字节流后，首先执行音频采样率对齐与格式标准化处理。经过预处理的音频与提示词（Prompt）共同输入多模态处理器，转化为模型可理解的高维张量（Tensors），为模型开启深度思考链路提供标准化的输入特征。

**2. 关键技术**
该模块基于 FastAPI 框架构建，推理逻辑采用 HuggingFace 的 `transformers` 库。系统在预处理阶段使用 `Qwen2_5OmniProcessor` 对音频进行采样率归一化（统一为 16kHz）及特征提取。为了提升并发处理能力，接口采用 `async` 异步模式，并利用 GPU 的显存加速技术完成计算。

**3. 核心代码**
```python
# llm_fastapi_omni.py：多模态推理与音频预处理逻辑
@app.post("/generate")
async def generate(prompt: str = Form(...), audio_file: UploadFile = File(None)):
    if audio_file:
        audio_bytes = await audio_file.read()
        # 将语音与文本统一转化为模型所需的张量
        inputs = processor(text=prompt, audios=[audio_bytes], return_tensors="pt").to("cuda")
    # 生成推理序列
    output_ids = model.generate(**inputs, max_new_tokens=2048)
    return {"result": processor.batch_decode(output_ids)[0]}
```

### 4.3.2 难度感知推理优化实现
**1. 功能描述**
难度感知优化是提升系统推理效率的核心策略。系统会对用户的输入请求进行实时复杂度评估，根据计算得出的难度系数动态调整推理策略。对于逻辑简单的常识性问题，系统采用较短的推理长度以节省算力；对于需要跨模态联想的复杂问题，系统则自动增加推理步长并开启全量“深度思考”模式，以确保输出质量的严密性。

**2. 关键技术**
优化逻辑引入了信息熵计算与任务类型分类器。系统通过分析 Prompt 中的逻辑词密度、领域专业度以及音频背景复杂度来量化难度。在生成阶段，系统通过动态调整 `max_new_tokens` 与采样温度（Temperature）等超参数，实现了计算资源与逻辑准确性之间的最优平衡。

**3. 核心代码**
```python
# 推理优化逻辑：基于任务难度动态调整参数
def optimize_inference(prompt_difficulty):
    # 根据难度量化值动态分配推理步长
    max_tokens = 512 if prompt_difficulty < 30 else 1024
    if prompt_difficulty > 80:
        max_tokens = 2048 # 开启极限思考模式
    return max_tokens
```

## 4.4 记录管理模块

### 4.4.1 历史记录持久化实现
**1. 功能描述**
历史记录管理模块实现了用户推理任务数据的闭环管理。在每次推理任务执行成功后，系统会自动捕获该次交互的上下文数据，包括用户的语音摘要、提示词、模型产生的完整思考链条（Thought Chain）以及最终答案。这些数据被结构化存储在关系型数据库中，为用户提供了随时回溯、复盘 AI 决策过程的可能性。

**2. 关键技术**
持久化层采用 Spring Data JPA 实现。系统设计了 `InferenceRecord` 实体类，利用 MySQL 的 `TEXT` 字段存储冗长的推理链条数据。为了提高存储效率与查询速度，系统通过数据库索引优化了用户 ID 与创建时间的检索链路，并支持在异步线程中执行保存操作，避免阻塞主业务流程。

**3. 核心代码**
```java
// InferenceRecordService.java：实现推理结果持久化
public void saveRecord(String username, String prompt, Map<String, Object> result) {
    InferenceRecord record = new InferenceRecord();
    record.setUsername(username);
    record.setPrompt(prompt);
    // 存储模型产生的深度思考路径
    record.setResultText((String) result.get("text"));
    record.setCreatedAt(LocalDateTime.now());
    repository.save(record);
}
```

历史记录展示模块为用户提供了直观的数据管理入口。用户可以通过前端的侧边抽屉组件，以时间倒序的方式浏览往期的所有推理任务。列表以卡片形式展示每个任务的摘要信息（如推理难度、答案首句等），并支持点击跳转以查看该次推理的完整波形、详细思考过程及模型反馈，提升了系统的整体可用性。

**2. 关键技术**
前端利用 Ant Design Vue 的 `Drawer` 抽屉组件与 `List` 列表组件进行 UI 布局。数据加载采用分页机制，通过 Axios 向后端请求特定范围内的历史数据。为了提升用户体验，组件内部实现了日期格式化过滤器，并结合响应式布局，确保在不同屏幕尺寸下均能清晰展示历史交互细节。
