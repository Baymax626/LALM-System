## 1. 项目概述

本项目旨在设计并实现一个基于 Qwen2.5-Omni 大模型的语音理解平台。平台通过集成先进的语音识别、自然语言处理和深度学习技术，构建一个能够接收用户语音输入，进行深度语义理解、逻辑推理，并以自然语言和可视化形式反馈结果的智能系统。

项目采用现代化的前后端分离架构，并为AI模型提供独立的服务层，确保系统的高内聚、低耦合，易于开发、测试和部署。

## 2. 整体技术架构

系统整体架构分为三个核心模块：**前端应用**、**后端服务**和**模型服务**。

```plaintext
[用户] <--> [浏览器]
   |
   |--- [前端应用 (Vue.js)] <--> [后端服务 (Java Spring Boot)] <--> [模型服务 (Python FastAPI)]
                                       |                                |
                                       |--- [数据库 (H2/PostgreSQL)]      |--- [Qwen2.5-Omni 模型]
```

**数据流与交互流程:**

1.  用户在**前端应用**中通过麦克风输入语音。
2.  前端将语音数据发送至**后端服务**。
3.  后端服务进行用户身份验证、记录请求，然后将核心语音/文本数据转发至**模型服务**。
4.  **模型服务**调用 Qwen2.5-Omni 模型进行语音识别、语义理解和推理。
5.  模型服务将处理结果（如：理解的文本、推理过程、答案）返回给后端服务。
6.  后端服务记录推理结果，并将其返回给前端应用。
7.  前端应用将结果以文本、图表等形式友好地展示给用户。

## 3. 模块详解

### 3.1. 前端应用 (Frontend)

前端是用户与系统交互的直接入口，负责提供一个直观、易用的操作界面。

-   **技术栈:**
    -   **框架:** Vue.js 3
    -   **构建工具:** Vite
    -   **UI 组件库:** (可根据 `package.json` 补充, 如 Element Plus, Ant Design Vue 等)
    -   **路由:** Vue Router
    -   **HTTP客户端:** Axios (封装在 `src/config/api.js`)

-   **核心功能模块 (`src/`):**
    -   **`views/Dashboard.vue`**: 系统主界面，整合了各个核心交互组件。
    -   **`views/Login.vue`**: 用户登录界面，提供系统访问入口。
    -   **`components/AudioInput.vue`**: 核心的音频输入组件，负责录制用户语音并将其发送到后端。
    -   **`components/ReasoningDisplay.vue`**: 用于展示模型“深度思考”过程的可视化组件。
    -   **`components/HistoryDrawer.vue`**: 展示用户历史查询记录的抽屉组件。
    -   **`router/index.js`**: 定义前端路由，管理页面跳转逻辑。

### 3.2. 后端服务 (Backend - Java)

后端服务是系统的“大脑”，负责处理核心业务逻辑、协调前端与模型服务之间的通信，并管理数据。

-   **技术栈:**
    -   **框架:** Spring Boot
    -   **构建工具:** Maven
    -   **数据持久化:** Spring Data JPA (Hibernate)
    -   **数据库:** (从 `application.properties` 和 `V1__init.sql` 推断，可能是 H2 或 PostgreSQL)

-   **核心功能模块 (`src/main/java/com/suda/lalm/`):**
    -   **`controller/`**: API 接口层。
        -   `LoginController`: 处理用户登录和认证。
        -   `InferenceController`: 接收前端的推理请求，并调用模型服务。
        -   `HealthController`: 提供健康检查接口。
    -   **`service/`**: 业务逻辑层。
        -   `UserService`: 封装用户相关的业务逻辑。
        -   `ModelService`: 封装与Python模型服务通信的逻辑。
        -   `InferenceRecordService`: 负责记录和查询用户的推理历史。
    -   **`repository/`**: 数据访问层。
        -   `UserRepository`: 访问用户信息。
        -   `InferenceRecordRepository`: 访问推理记录数据。
    -   **`entity/`**: 数据实体类，映射到数据库表。
        -   `User`: 用户实体。
        -   `InferenceRecord`: 推理记录实体。
    -   **`config/`**: 配置类。
        -   `CorsConfig`: 配置跨域资源共享。

### 3.3. 模型服务 (Model Service - Python)

模型服务是实现本项目核心AI能力的独立单元，它将复杂的Qwen2.5-Omni模型封装成一个简单易用的Web服务。

-   **技术栈:**
    -   **Web框架:** FastAPI
    -   **ML/DL框架:** PyTorch, Transformers
    -   **服务器:** Uvicorn

-   **核心功能模块 (`model_service/`):**
    -   **`llm_fastapi_omni.py`**: FastAPI应用主文件，定义了用于接收语音/文本并进行推理的API端点。
    -   **`offline_omni_infer.py`**: 支持离线进行模型推理的脚本，便于调试和批量测试。
    -   **`deploy/qwen_omni_utils.py`**: 封装了与Qwen2.5-Omni模型交互的特定工具函数。
    -   **`requirements-model.txt`**: 详细列出了运行模型服务所需的所有Python依赖。
